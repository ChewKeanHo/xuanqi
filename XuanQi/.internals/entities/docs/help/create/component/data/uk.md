# Розділ довідки щодо створення компонента даних

Це розділ довідки щодо створення компонента даних або
незалежно, або як частина іншого більшого компонента. Щоб
включити частину даних, просто введіть `data` у значення `[TYPES]`.
Приклад:

```
# шаблон команди
$ [XuanQi] create component [TYPES] [NAME]

# лише компонент даних
$ [XuanQi] create component data [NAME]

# з частиною даних всередині складеного компонента
$ [XuanQi] create component "...,data,..." [NAME]
```




## Мета

Компонент даних призначений головним чином для полегшення проекту та
компонента з певним набором даних. Це дозволяє змінні зміни рендерингу
для тих самих макетів файлів, роблячи вибір виводу надійним
без жертвування підтримуваністю. XuanQi має вбудовані засоби
для імпорту всіх файлів конфігурації (`.conf`) та функцій shell-скриптів
(`.sh`) безперешкодно.

Загалом, XuanQi розглядає компонент даних як сховище даних
**без бази даних** (`noDB`).




## Структури файлів

Компонент даних відповідає наступній структурі файлів за замовчуванням:

```
[XUANQI_PATH_COMPONENTS]
└── [XUANQI_COMPONENT_NAME]
       ├── Data
       │    ├── i18n
       │    │     ├── title.sh
       │    │     └── ...
       │    ├── sample.conf
       │    └── ...
       └── XuanQi
            └── import.sh
```

* директорія компонента — `Data`.
* shell-скрипт оператора компонента знаходиться безпосередньо всередині
  `XuanQi/import.sh`. Він є частиною ініціалізації компонента.




## Основна мета

Ваша **основна мета — абстрагувати джерела змінних даних
та створити засіб даних для вашого проекту або ваших компонентів**.
Як це зробити, повністю залежить від вас.

Під час ініціалізації кожного компонента будь-який компонент може
аналізувати компонент даних зсередини або через інші компоненти.
Тому ви **ПОВИННІ** завжди підтримувати директорію даних гнучкою
та аналізованою.

Ви можете звернутися до `XuanQi/.internals/API` проекту для доступних
API.




## Файл конфігурації або Shell-скрипт

XuanQi надає 2 основні способи роботи з управлінням даними:

* файл конфігурації (`.conf`)
* файл функцій shell-скрипта (`.sh`)

`.conf` підходить для швидкого налаштування змінних, щоб ви могли
негайно використовувати його значення для рендерингу файлів. Зразок
файлу (`Data/sample.conf`) створюється для того, як створити один.
**Один файл повинен містити лише одну пару ключ:значення**.

`.sh` насправді є shell-скриптом, що містить визначення функції
для надання даних шляхом логічного обумовлення. Це найбільш підходить,
якщо ваш набір даних вимагає однієї або більше умов для рендерингу
виводу по-різному (наприклад, функції `i18n_` залежать від прапору
`$XUANQI_CONTENT_LANGUAGE` для повернення рядка, специфічного для мови).
**БУДЬТЕ ОБЕРЕЖНІ: функції з однаковими іменами будуть перевизначені
під час імпорту**. Зразок файлу (`Data/i18n/title.sh`) створюється для
вашого ознайомлення.

Останній варіант — це ручне читання файлів `.txt` всередині директорії.
XuanQi буде аналізувати лише `.conf` та `.sh`, тому ви можете безпечно
використовувати його. Це робиться шляхом організації певної назви набору
даних як назви директорії та залишення імені файлу строго як назви
параметра. Недоліком є те, що цей метод займає більше трафіку
введення/виведення на читання/запис, що може уповільнити виробництво.
Однак *виконання вимог завжди перед швидкістю*, тому ви все одно можете
розглянути можливість його використання, коли це потрібно. Приклад
підходу i18n на основі текстових файлів:

```
[XUANQI_PATH_COMPONENTS]
└── [XUANQI_COMPONENT_NAME]
       ├── Data
       │    ├── names
       │    │     ├── de.txt
       │    │     ├── en.txt
       │    │     ├── es.txt
       │    │     └── ...
       │    └── ...
       └── ...

# використання вищезазначеного в shell-скрипті
____name="$( \\
    XuanQi_Data_Read_Raw \\
        "${XUANQI_COMPONENT_PATH}/Data/names/${XUANQI_CONTENT_LANGUAGE}.txt" \\
)"
```



### Як вибрати

Завжди використовуйте `.conf` за замовчуванням і коли це можливо.
Якщо є логічна вимога (наприклад, умова тощо), то використовуйте
`.sh`.




## Медіафайли

Хоча технічно медіафайли (наприклад, зображення, аудіо, відео тощо)
є даними, **будь ласка, УНИКАЙТЕ розміщення їх тут**. Існує
виділений компонент `media` з виділеними функціями обробки для
нього. Будь ласка, використовуйте його натомість.

Ви завжди повинні ставитися до компонента даних як до **без бази
даних** (`noDB`).
