# Өгөгдлийн Компонент Үүсгэх Тусламжийн Хэсэг

Энэ нь өгөгдлийн компонентийг бие даан эсвэл өөр том компонентийн
нэг хэсэг болгон үүсгэх тусламжийн хэсэг юм. Өгөгдлийн хэсгийг
оруулахын тулд `[TYPES]` утгад `data`-г оруулна уу. Жишээ нь:

```
# командын загвар
$ [XuanQi] create component [TYPES] [NAME]

# зөвхөн өгөгдлийн компонент
$ [XuanQi] create component data [NAME]

# нийлмэл компонент дотор өгөгдлийн хэсэгтэй
$ [XuanQi] create component "...,data,..." [NAME]
```




## Зорилго

Өгөгдлийн компонент нь голчлон төсөл болон компонентийг тодорхой
өгөгдлийн багцаар хангахад зориулагдсан. Энэ нь ижил файлын загваруудад
хувьсах рендер хийх өөрчлөлтийг боломжтой болгож, засвар үйлчилгээг
эрхэмлэхгүйгээр гаралтын сонголтыг бат бөх болгодог. XuanQi нь бүх
тохиргооны файлууд (`.conf`) болон shell скрипт (`.sh`) функцуудыг
зэрэгцүүлэн импортлох суурилуулсан боломжтой.

Ерөнхийдөө XuanQi нь өгөгдлийн компонентийг **өгөгдлийн сангуй**
(`noDB`) өгөгдлийн хадгалах газар гэж үздэг.




## Файлын Бүтэц

Өгөгдлийн компонент дараах анхны файлын бүтцийг баримтална:

```
[XUANQI_PATH_COMPONENTS]
└── [XUANQI_COMPONENT_NAME]
       ├── Data
       │    ├── i18n
       │    │     ├── title.sh
       │    │     └── ...
       │    ├── sample.conf
       │    └── ...
       └── XuanQi
            └── import.sh
```

* компонентийн директор нь `Data` байна.
* компонентийн оператор shell скрипт нь шууд `XuanQi/import.sh`
  дотор байрлана. Энэ нь компонентийн эхлүүлэлтийн нэг хэсэг юм.




## Үндсэн Зорилт

Таны **үндсэн зорилт нь хувьсах өгөгдлийн эх үүсвэрүүдийг абстракт
хэлбэрт оруулах бөгөөд таны төсөл эсвэл компонентуудад зориулсан
өгөгдлийн байгууламжийг үүсгэх** юм. Үүнийг хэрхэн хийх нь бүрэн
танаас хамаарна.

Компонент бүрийн эхлүүлэх үед аливаа компонент нь өгөгдлийн
компонентийг дотроос эсвэл бусад компонентуудаас задлан шинжлэх
боломжтой. Тиймээс та өгөгдлийн директорыг бүх цаг үед уян хатан,
задлан шинжлэх боломжтой байлгах **ЁСТОЙ**.

Боломжит API-уудын тулд төслийн `XuanQi/.internals/API`-г үзэх боломжтой.




## Тохиргооны Файл эсвэл Shell Скрепт

XuanQi нь өгөгдлийн менежменттэй ажиллах 2 үндсэн аргыг санал
болгодог:

* тохиргооны файл (`.conf`)
* shell скрипт функцийн файл (`.sh`)

`.conf` нь хувьсагчуудыг хурдан тохируулахад тохиромжтой бөгөөд
файлын рендерлэхэд түүний утгыг нэн даруй ашиглах боломжтой.
Жишээ файл (`Data/sample.conf`) нь хэрхэн үүсгэхийг харуулахын
тулд үүсгэгдсэн. **Нэг файлд зөвхөн нэг түлхүүр:утгын хос байх ёстой**.

`.sh` нь үнэндээ логик нөхцөлөөр өгөгдөл өгөх функцийн тодорхойлолтыг
агуулсан shell скрипт юм. Энэ нь таны өгөгдлийн багц нь гаралтыг өөрөөр
рендерлэхэд нэг эсвэл хэд хэдэн нөхцөл шаарддаг үед хамгийн тохиромжтой
(жишээ нь `i18n_` функцууд нь `$XUANQI_CONTENT_LANGUAGE` дарганд
хамааран тухайн хэлний тэмдэгт мөрийг буцаадаг). **АНХААР: ижил нэртэй
функцууд импортлох үед давамгайлна**. Жишээ файл (`Data/i18n/title.sh`)
нь таны лавлагааны тулд үүсгэгдсэн.

Сүүлийн сонголт нь директор доторх `.txt` файлуудыг гарын авлагаар
унших байх болно. XuanQi нь зөвхөн `.conf` болон `.sh`-г задлан
шинжлэх тул та аюулгүй ашиглах боломжтой. Энэ нь тодорхой өгөгдлийн
багцын нэрийг директорын нэр болгон зохион байгуулж, файлын нэрийг
параметрийн нэр болгон хатуу үлдээх замаар хийгддэг. Сул тал нь энэ
арга нь илүү их IO унших/бичих хөдөлгөөнийг эзэлдэг бөгөөд
үйлдвэрлэлийг удаашруулж болно. Гэсэн хэдий ч *шаардлагыг хангах нь
үргэлж хурдаас урд* ирдэг тул шаардлагатай үед үүнийг ашиглахыг
харж болно. Текст файл дээр суурилсан i18n аргын жишээ:

```
[XUANQI_PATH_COMPONENTS]
└── [XUANQI_COMPONENT_NAME]
       ├── Data
       │    ├── names
       │    │     ├── de.txt
       │    │     ├── en.txt
       │    │     ├── es.txt
       │    │     └── ...
       │    └── ...
       └── ...

# дээрхийг shell скриптэд ашиглах
____name="$( \\
    XuanQi_Data_Read_Raw \\
        "${XUANQI_COMPONENT_PATH}/Data/names/${XUANQI_CONTENT_LANGUAGE}.txt" \\
)"
```



### Хэрхэн Сонгох

Анхны байдлаар болон боломжтой үргэлж `.conf`-г ашиглана уу.
Хэрэв логик шаардлага (жишээ нь нөхцөл г.м) байвал `.sh`-г
ашиглана уу.




## Медиа Файлууд

Техникийн хувьд медиа файлууд (жишээ нь зураг, аудио, видео
г.м) нь өгөгдөл боловч **энд байрлуулахыг ЗАЙЛСАН ТУШ**. Үүний
тулд зориулсан боловсруулах функц бүхий зориулсан `media`
компонент байдаг. Оронд нь үүнийг ашиглана уу.

Та өгөгдлийн компонентийг үргэлж **өгөгдлийн сангуй** (`noDB`)
гэж үзэх ёстой.




## Эпилог

Өгөгдлийн компонент үүсгэх тусламжийн хэсэг дууслаа.
