# Раздел справки по созданию компонента данных

Это раздел справки по созданию компонента данных либо
независимо, либо как часть другого более крупного компонента.
Чтобы включить часть данных, просто введите `data` в значение
`[TYPES]`. Пример:

```
# шаблон команды
$ [XuanQi] create component [TYPES] [NAME]

# только компонент данных
$ [XuanQi] create component data [NAME]

# с частью данных внутри составного компонента
$ [XuanQi] create component "...,data,..." [NAME]
```




## Цель

Компонент данных в основном предназначен для облегчения проекта и
компонента с определенным набором данных. Это позволяет изменять
переменные рендеринга для одних и тех же макетов файлов, делая
выбор вывода надежным без ущерба для сопровождаемости. XuanQi
имеет встроенные средства для беспрепятственного импорта всех
файлов конфигурации (`.conf`) и функций скриптов оболочки (`.sh`).

В общем, XuanQi рассматривает компонент данных как хранилище данных
**без базы данных** (`noDB`).




## Структуры файлов

Компонент данных соответствует следующей структуре файлов по
умолчанию:

```
[XUANQI_PATH_COMPONENTS]
└── [XUANQI_COMPONENT_NAME]
       ├── Data
       │    ├── i18n
       │    │     ├── title.sh
       │    │     └── ...
       │    ├── sample.conf
       │    └── ...
       └── XuanQi
            └── import.sh
```

* директория компонента — `Data`.
* скрипт оболочки оператора компонента находится непосредственно внутри
  `XuanQi/import.sh`. Это часть инициализации компонента.




## Основная цель

Ваша **основная цель — абстрагировать источники переменных
данных и создать механизм данных для вашего проекта или ваших
компонентов**. Как это сделать, полностью зависит от вас.

При инициализации каждого компонента любой компонент может
анализировать компонент данных изнутри или через другие компоненты.
Поэтому вы **ДОЛЖНЫ** всегда сохранять директорию данных гибкой и
анализируемой.

Вы можете обратиться к `XuanQi/.internals/API` проекта для получения
доступных API.




## Файл конфигурации или скрипт оболочки

XuanQi предоставляет 2 основных способа управления данными:

* файл конфигурации (`.conf`)
* файл функций скрипта оболочки (`.sh`)

`.conf` подходит для быстрой настройки переменных, чтобы вы могли
немедленно использовать их значение для рендеринга файлов. Пример
файла (`Data/sample.conf`) создан для демонстрации того, как его
создать. **Один файл должен содержать только одну пару ключ:значение**.

`.sh` на самом деле представляет собой скрипт оболочки, содержащий
определение функции для предоставления данных путем логического
обусловливания. Это наиболее подходит, если ваш набор данных требует
одного или нескольких условий для рендеринга вывода по-разному
(например, функции `i18n_` зависят от флага `$XUANQI_CONTENT_LANGUAGE`
для возврата строки, специфичной для языка). **БУДЬТЕ ОСТОРОЖНЫ:
функции с одинаковыми именами будут переопределены во время
импорта**. Пример файла (`Data/i18n/title.sh`) создан для
вашего ознакомления.

Последний вариант — вручную читать файлы `.txt` внутри директории.
XuanQi будет анализировать только `.conf` и `.sh`, так что вы можете
безопасно их использовать. Это делается путем организации определенного
имени набора данных в качестве имени директории и строгого оставления
имени файла в качестве имени параметра. Недостатком является то, что
этот метод занимает больше трафика ввода-вывода на чтение/запись, что
может замедлить производство. Однако *выполнение требований всегда
превыше скорости*, так что вы все равно можете рассмотреть возможность
его использования, когда это необходимо. Пример подхода i18n на основе
текстовых файлов:

```
[XUANQI_PATH_COMPONENTS]
└── [XUANQI_COMPONENT_NAME]
       ├── Data
       │    ├── names
       │    │     ├── de.txt
       │    │     ├── en.txt
       │    │     ├── es.txt
       │    │     └── ...
       │    └── ...
       └── ...

# использование вышеуказанного в скрипте оболочки
____name="$( \\
    XuanQi_Data_Read_Raw \\
        "${XUANQI_COMPONENT_PATH}/Data/names/${XUANQI_CONTENT_LANGUAGE}.txt" \\
)"
```



### Как выбрать

Всегда используйте `.conf` по умолчанию и когда это возможно. Если есть
логическое требование (например, условие и т. д.), то используйте `.sh`.




## Медиафайлы

Хотя технически медиафайлы (например, изображения, аудио, видео и т. д.)
являются данными, **пожалуйста, ИЗБЕГАЙТЕ размещать их здесь**. Существует
выделенный компонент `media` с выделенными функциями обработки для этого.
Пожалуйста, используйте его вместо этого.

Вы должны всегда рассматривать компонент данных как **без базы данных**
(`noDB`).
